This seems to do the trick for a cold boot or start from parked. However for a short stop start scenario this will not help as the CMU appears to wake from some kind of sleep state with the headunit apparently running? In headunit-wrapper I put a 10s delay on startup (9 + 1) followed by polling every 1s.

\# allow delay for loading of headunit before polling
  sleep 9

\# loop forever. check for headunit running ever second
while true
do
  sleep 1
  check_headunit=`ps|grep 'bin/headunit'|grep -v wrapper|grep -v grep|wc -l|awk '{print $1}'`

  [ $check_headunit -eq 0 ] && start_headunit

\#  RAND=`expr $RANDOM % 5 + 10`

done

### ixnewton – 2019-09-26T21:19:08Z

[Originalkommentar](https://github.com/Trevelopment/MZD-AIO/issues/63#issuecomment-535690276) · Aktualisiert: 2019-09-27T14:11:14Z

Update to the headunit-wrapper fixing the test for a running headunit using "ps ax" to get the right 1/0 result. Startups are now more consistent both from cold start and re-start after a short stop. To be sure only one instance ever gets started there is a "killall -q -9 headunit" before launching a new instance. Still using a swapfile on a USB drive to maintain extra memory. Removing it caused some unexpected white screen freezes on warm startup.

```
start_headunit()
{
  sed -i 's."wifiTransport": true."wifiTransport": false.g' /tmp/root/headunit.json
  killall -q -9 headunit
  sync; echo 3 > /proc/sys/vm/drop_caches
  taskset 0xFFFFFFFF ionice -c 1 -n 0 nice -n -20 "${SCRIPTPATH}/headunit" "$@" >> ${LOGPATH} 2>&1 &
  echo "Start Headunit (USB Mode)"  >> ${LOGPATH}
}

# prevent conflict by Official AA
killall -q -9 aap_service carplayd L_jciCARPLAY L_jciAAPA

# loop forever. check for headunit running every 5 seconds
while true
do
  check_headunit=`ps ax|grep 'bin/headunit'|grep -v wrapper|grep -v grep|wc -l|awk '{print $1}'`
  [ $check_headunit -eq 0 ] && start_headunit
  sleep 5
done
```
